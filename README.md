# 퀘스트 · 1단계 기반 리팩터링

## 월간 캘린더 날짜별 기록 (2026-11-02)

- 경로: **캘린더 → 월 → 날짜 숫자(날짜 눌러 기록 보기)**. 날짜 버튼은 키보드로도 동작하며 현재 월·탐색 상태는 시트를 닫아도 유지됩니다. 작은 개수는 저널·게시 스토리·완료 항목 합계이며 예정 태스크는 제외합니다.
- 시트: 저널 / 스토리 / 완료(데일리·태스크·메인·서브) / 예정 태스크. 저널은 저장된 `date`의 정확한 `YYYY-MM-DD`만 사용하고 `at`·문서 ID로 추정하지 않습니다. 같은 날의 복수 저널도 모두 표시하고 읽기 전용 상세를 엽니다. 스토리는 내 게시물의 `createdAt` 한국 날짜이며 저널 공유도 별도의 게시 기록일 뿐 완료 증거로 세지 않습니다.
- 데일리는 `done[YYYY-MM-DD]` 기록 날짜를 사용합니다. 완료 후 요일·활성 상태를 바꿔도 기존 이력을 유지합니다. 태스크는 `done === true`와 실제 `doneAt`, 메인·서브는 `status === 'done'`과 `doneAt`을 사용합니다. `due`·`end`·생성일로 완료일을 추정하지 않습니다. 기간 태스크도 완료일에 표시됩니다.
- 완료 시각이 없는 과거 태스크·목표는 날짜별 목록/개수에서 제외하고 **날짜 미확인 · 전체 과거 완료** 접이 영역에 별도 표시합니다. 소급 날짜 채우기·마이그레이션은 하지 않습니다. 기존 완료 토글은 완료 시 `doneAt`을 저장하고 취소 시 `null`로 비웁니다. 단순 편집·조회는 이 값을 변경하지 않습니다.
- 순수 선택기 `src/day-activities.js`는 개인 컬렉션 및 명시적 소유자 필터와 게시물/목표 소유자 검사를 사용합니다. 소유자 없는 `mine`은 기존 계약상 현재 계정의 개인 데이터입니다. 서버 접근 제어를 추가한 것은 아닙니다.
- **일별 일정 보기·추가**로 기존 시간표·태스크 추가를 유지하며 캘린더 태스크 행의 날짜·시간 배지는 계속 생략합니다. 조회 경로는 API 쓰기·보상 지급 없이 동작합니다. 기존 경제 금액·원장·저장 스키마는 변경하지 않았습니다.
- 검증 범위: 순수 날짜 선택기와 실제 번들 위임 클릭 테스트, 기존 캘린더/경제 회귀 테스트. 모바일 스크롤 상한·줄바꿈은 스타일 계약으로 검사하며 실제 모바일 브라우저 시각 검증은 별도입니다.

## 경제 엔진 통합 · 승인 정책 갱신 (2026-11-02)

승인된 5단계 경제 정책을 `src/economy.js`와 런타임 쓰기 경계에 통합했습니다. **정확한 지급표·한도·소스 계약·마이그레이션·알려진 한계는 [ECONOMY.md](ECONOMY.md)**를 참고하세요. 기존 온보딩·마감일·태스크 시간·캘린더 표시 정책은 유지합니다.

- 데일리 XP·코인 각각 5/10/15/20/25. 태스크 XP·코인 각각 10/20/30/40/50. 저널 10 XP/5 코인. 일일 XP·코인 총액·완료 횟수 제한 없음.
- 최대 레벨 100(누적 106,920 XP), 기존 곡선 `100*(L-1)+10*(L-1)*(L-2)` 유지. 이후에도 총 XP 누적, 진행도 100%·MAX 표시. 환생·레벨업 코인 없음.

|---|---|---|

`src/economy.js`의 `DAILY_DIFFICULTY` / `TASK_DIFFICULTY`를 선택기·기존 기록 아이콘·도움말에 사용합니다. 공용 `LABELS`는 호환용으로만 남깁니다. `TIERS`·이름·막대와 저장 구조는 그대로이며 새 지급만 정책 2를 적용합니다.

### 공용 난이도 선택기 (2026-11-02)
- 모든 아이콘은 고정 24×16 SVG 안의 높이가 증가하는 직사각형 5개입니다. 기하는 같고 단계에 따라 왼쪽부터 1~5개만 활성화합니다. 활성은 실제 테마 변수 `--accent`, 비활성은 `--track`이며 단계별 색상·원·메달·이모지는 쓰지 않습니다.
- 선택 설명: 부담 거의 없음 / 가벼운 노력 / 적당한 집중 / 상당한 노력 / 큰 시간·집중 필요. 데일리는 반복할 때 드는 시간과 부담, 태스크는 한 번 끝내는 시간과 집중으로 판단합니다.
- 생성·수정·중첩 태스크 등 8곳 모두 공용 `difficultySelector`를 사용합니다. 버튼 내부 지급량이 갱신되고 작성 중 이름·메모·부모 초안은 보존합니다. 아래쪽 설명 행은 추가하지 않습니다.
- `activityRewardPreview`는 읽기 전용이며 첫 완료·주간 추가 보너스를 제외한 기본 지급량을 제한 없이 계산합니다. 휴식일은 0이며 기존 완료 수정·재완료의 지급량 보존 규칙은 바꾸지 않습니다.
- 시각 확인: `dist/quest-demo.html`을 열고 **오늘 → 데일리 퀘스트 추가** 또는 **태스크 추가**를 누릅니다. 기존 항목을 누르면 수정 선택기, 메인 퀘스트 추가 → 태스크 추가에서는 중첩 선택기를 볼 수 있습니다. 로그인 미리보기에서는 카카오톡 가입 미리보기 → 닉네임 입력 → 모험 시작하기 후 같은 경로입니다.

- 최초 실제 완료 30 코인 유지. 메인 생성 20 XP/10 코인, 서브 생성 10 XP/5 코인. 메인 완료 200 XP/100 코인, 서브 완료 60 XP/30 코인. 생성·완료 주간 횟수와 최소 활동일 조건 없음. 같은 목표는 평생 한 번 판정하며 완료 버튼의 직접 확인을 신뢰합니다. 별도 증빙 검증·필수 메모 없음.
- 주간 활동 3일 60 XP/30 코인, 5일 추가 40 XP/20 코인 자동 지급. 소셜 보상·유료 휴식권 제거, 무료 휴식 계획 제공.
- 상점 꾸미기/나의 보상/보관함/내역, 실제 CSS 꾸미기, 빈 개인 보상 가격·5 단위 검증·가격 도움말·예정/사용/환불·횟수 제한 구현.
- 기존 7개 컬렉션과 v2 저장 키 유지, 선택 최상위 `economy` 원장 추가. 기존 XP·코인은 한 번 baseline으로 보존하고 과거 보너스는 소급 지급하지 않습니다. 완료 취소는 실제 지급량 회수, 재완료는 원래 지급량 복원. 기록 삭제는 성장 회수 아님.
- 한국 날짜/월요일 주 기준 시각 주입. 보안 서버·위변조 방지·현금 교환이 아닌 로컬 개발판입니다. 유료 이미지 호출 없음.

기존 화면·스타일과 주요 UI 클로저를 유지하고, 데이터·실행 환경·데모를 명시적 ES 모듈로 분리한 로컬 개발판입니다. 리디자인이나 백엔드 구현이 아닙니다.

## 실행

Node.js 22 이상. 외부 npm 패키지 설치 불필요.

```sh
npm run build
npm run check
npm test
npm run dev
```

- 개발 서버: `http://localhost:4173/` (새 작업 공간은 로그인 화면, 기존 프로필은 일반 홈), `http://localhost:4173/demo.html` (명시적 가상 데이터).
- 단일 파일 실행: `dist/quest.html`, `dist/quest-demo.html`을 브라우저에서 열기. JS/CSS는 인라인이며 형제 파일이 필요하지 않습니다.
- 기존 Google Fonts 링크는 디자인 보존을 위해 유지했습니다. 오프라인에서는 시스템 글꼴로 대체됩니다. 실제 인증/업무 데이터 서버는 없습니다. 일반 화면의 사진 버튼은 안내만 표시하며 사진 선택·전송·API 호출·과금을 하지 않습니다.
- `file://` 저장 동작은 브라우저별로 다릅니다. 저장 차단 시 오류를 표시하며 성공으로 위장하지 않습니다. 안정적인 개발은 위 서버를 사용하세요.
- ZIP 재생성: `node scripts/package.mjs` (상위 폴더에 `quest-foundation.zip`).

## 원본 보존

### 로그인 / 캐릭터 만들기 진입점

- `/` 또는 `/dist/quest.html`: 저장된 프로필이 없으면 로그인, 있으면 기존 홈/요청한 일반 화면을 유지합니다.
- `/?screen=login`: 데이터 삭제 없이 로그인 UI만 다시 엽니다. 로그인 후에는 기존 프로필 유무와 무관하게 캐릭터 만들기로 이동합니다.
- `/?screen=character`: 일반 캐릭터 만들기 직접 진입.
- `/dist/login-preview.html`: 별도 저장 키 `quest:preview:login:20261101`을 사용하며 새로고침할 때마다 로그인으로 진입합니다. 이 미리보기에서 만든 진행 내용은 보존하며 기본 작업 공간과 섞지 않습니다.
- 로그인 화면은 `로그인` 1개와 회원가입 수단 `카카오톡으로 가입하기` 1개만 제공합니다. 두 버튼 모두 인증 정보 입력이나 계정 생성 없이 캐릭터 화면으로 이동합니다. 카카오 버튼은 미연결 안내도 표시합니다. **실제 카카오 OAuth·회원가입·로그인·인증 세션은 구현하지 않았습니다.**
- 상단에 `개발 미리보기 · 실제 인증 미연결`을 표시합니다. 프로필 저장 전에는 일반 상단 메뉴·내비게이션을 숨깁니다. 일반 캐릭터 만들기는 미리보기·닉네임·옷 색·시작 버튼으로 구성하며, 사진 버튼에는 `사진 기반 생성은 개발 테스트에서만 이용할 수 있어요`를 표시합니다. 기본 캐릭터로 시작할 수 있습니다.
- `npm run build`는 두 기본 번들과 두 미리보기 파일을 함께 생성합니다. 별도 재생성은 `npm run login-preview`, `npm run image-start-preview`입니다. 유료 실생성은 검증에 사용하지 않습니다.

최초 원본은 `../quest/index-before-preview-sync.html`에 보존하며, `../quest/index.html`은 `node scripts/refresh-preview.mjs`로 최신 빌드에 동기화합니다. 보존 원본 SHA-256:

`8f43bd89c5c6b6261c8c160afe09c9cb7868ce6c227e6417baf6d300ffd99452`

ZIP에는 원본 업로드가 포함되지 않습니다. 원본 해시 테스트는 원본이 옆에 있을 때 실행되고, 배포 ZIP만 풀었을 때는 해당 테스트 1개만 명시적으로 건너뜁니다. 빌드는 원본에 의존하지 않습니다.

- 설정: 각 키의 `:preferences` 하위 키. `lq2:*`를 읽거나 쓰지 않습니다.
- `quest:v1`을 자동으로 읽거나 덮어쓰지 않습니다. 예전 데이터는 원본 앱에서 JSON으로 내보낸 뒤 새 앱의 **설정 → 백업 가져오기**에서 직접 파일을 선택해야 합니다.
- v2 스냅샷은 `v`, `at`와 `profiles/projects/feed/replies/follows/mine/media` 7개 사전 컬렉션 및 선택 `economy` 객체로 구성됩니다. 프로필 키는 로컬 UI 호환 ID인 `me`이며 계정 ID나 인증 수단이 아닙니다. 첫 실행 프로필 컬렉션은 비어 있고 사용자가 직접 만듭니다.
- JSON 구조·버전·컬렉션·주요 문서 필드·ID·이미지 형식·중첩/크기·위험 키를 검증합니다. 전체 업무 스키마 검증기나 악성 콘텐츠 정화 엔진은 아닙니다. 신뢰할 수 있는 백업만 사용하세요.
- 이전 v1 백업은 **파일 가져오기에 한해서만** 읽습니다. 예전 `ax` 월별 묶음은 메모리에서 일반 문서로 펼쳐 v2로 저장합니다. 자동 묶음/보관/정리 타이머는 제거했습니다.
- 350ms 지연 저장을 없앴습니다. CRUD는 동기 localStorage flush에 실패하면 거부되고, 해당 API가 작성한 새 상태는 반영하지 않습니다. 백업은 현재 메모리 상태를 캡처하므로 지연 스냅샷을 내보내지 않습니다.
- 게시물 삭제는 해당 `id~` 이미지와 답글만 정리합니다. 다른 게시물·프로필 이미지·다른 작업 공간은 유지합니다. 프로젝트 삭제 시 공유하지 않는 표지 정리 및 연결된 태스크의 프로젝트 참조 해제를 수행합니다.
- 초기화는 현재 작업 공간만 빈 v2 상태로 저장하고 설정 키를 지웁니다. 데모 초기화 후에도 재시드하지 않습니다. 다른 작업 공간·원본 v1 키에는 영향이 없습니다.

## 반영 범위

- 기존 일반 화면·스타일·네비게이션 보존. 상단에 `개발 미리보기 · 실제 인증 미연결` 안내, 데모에서는 가상 데이터 표시.
- Claude SDK 호출·계정/권한·이름 조회 기능 및 `userCap`, `resolveNames` 의존성 제거.
- 기본 번들에서 fixture 모듈과 가상 인물·프로젝트·기록 문자열 제외.
- 가짜 시간차 반응/댓글 제거. 기존 화면 갱신·애니메이션·포커스 타이머는 유지.
- 새 저널/수치 기록의 공유 기본값은 false, 직접 만드는 로컬 프로필의 비공개 표시 기본값은 true.
- 삭제된 더보기 설정 버튼·주간 리뷰 화면은 되살리지 않음. 주간 리뷰의 미사용 함수도 제거.
- 추가 화면의 태스크/서브/메인 종류 전환 행 제거(각 진입 종류·태스크 연결 선택·서브 부모 선택 유지). 태스크의 메인/서브 연결 태그는 모든 표시 경로에서 제거하고, 시간이 있을 때만 공용 `taskTimeTag(m)`로 기존 `tmLabel` 형식의 작은 시간 배지 하나를 표시합니다. 중첩·간소화·완료·이월 표시와 주·월 캘린더·초안·스토리 참조에도 적용하며, 시간이 없는 기존 참조에는 배지를 만들지 않습니다. 제목·날짜·메모와 퀘스트 연결 데이터·선택기는 유지합니다.

## 구현하지 않은 것 / 위험

### 캐릭터 · 프로필 사진

사진 기반 AI 캐릭터 생성(Genspark)은 제거했습니다. 사진 업로드는 기기 안에서 크기만 줄여 프로필 사진으로 저장하며 외부로 전송하지 않습니다.

온보딩은 데스크톱 스토리/프로필과 동일한 실제 `#app[data-v="profile"]` 래퍼(최대 600px)를 사용합니다. 닉네임 예시 문구는 제거했습니다. 사진 업로드와 촬영은 개발 화면에서만 별도 입력을 열며 전송 동의를 먼저 확인합니다. 일반 화면에는 코드·비용·전송 동의 설정이 없고 사진 기능은 안내만 표시합니다. 캔버스 얼굴 필터·가짜 생성 대기 시간·원본 미저장 보장은 제거했습니다.

**실제 로그인·서버·사용자별 접근 제어·팔로우 승인·서버 권한 검사·새로운 기록별 비공개 모델은 구현하지 않았습니다.** 공개/공유 관련 기존 UI는 로컬 표시·로컬 피드 작성 동작뿐입니다. 설정에 이를 명시했습니다. 민감한 실데이터를 넣는 운영판이 아닙니다.

- UI 클로저는 의도적으로 유지했습니다. 순수 도메인/뷰 컴포넌트 분해는 후속 단계입니다.
- 기존 UI 일부의 낙관적 상태 변경 및 오류를 삼키는 보조 동작은 남아 있습니다. 어댑터의 한 호출만 원자적이며 여러 API를 연달아 호출하는 사용자 동작 전체는 트랜잭션이 아닙니다.
- 여러 탭 동시 편집은 마지막 쓰기 우선이고 동기화·충돌 감지가 없습니다.
- localStorage 용량 제한, 브라우저 삭제/비공개 모드/파일 경로별 저장 차이가 있습니다. 이미지가 많으면 용량 초과할 수 있습니다. 자주 백업하세요.
- 동기 JSON 전체 저장은 데이터가 커지면 느려질 수 있습니다. IndexedDB/서버 전환은 후속 작업입니다.
- 프로필 사진 교체·보상 이미지 등 모든 도메인의 참조 카운팅/고아 미디어 수집은 구현하지 않았습니다.
- 기존 사진 처리, 달력, 드래그, 모바일 파일 선택, 다운로드와 실제 브라우저 렌더 배치는 추가 수동 검증이 필요합니다.

## 향후 백엔드 계약

1. `runtime.createAPI`의 메서드 표면을 유지하되 `identity`를 고정 로컬 ID가 아닌 서버 검증 세션에서 주입합니다. 클라이언트의 author/owner 필드는 신뢰하지 않습니다.
2. 서버가 레코드별 visibility·소유권·팔로우 승인·차단·읽기/쓰기 권한을 강제합니다. 현재의 `private`/`share` UI 플래그는 보안 경계가 아닙니다.
3. API는 저장 확인된 정규화 문서/버전 또는 명시적 오류를 반환합니다. 멱등 키·충돌 버전·복합 트랜잭션·재시도/오프라인 정책을 정의해야 합니다.
4. 미디어 업로드/참조 삭제를 별도 저장 계약으로, 백업은 서버 스키마 버전과 검증/가져오기 정책으로 확장합니다. 자동 레거시 가져오기는 계속 금지합니다.

## 검증

`npm run build && npm run check && npm test`

승인 정책 갱신 후 **205개 통과 / 실패 0 / 건너뜀 0**, 구문 검사 **30개 모듈 + 인라인 번들 4개**입니다. 공통 이름·막대·선택기와 초안 보존, 각 200회 무제한 지급, 목표 주간 횟수 초과·평생 중복 방지, 과거 원장 금액 복원, 99/100/초과 레벨과 실제 UI 완료를 검증합니다. 검증 명령은 `npm run build`, `npm run check`, `npm test`이며 미리보기 3종과 ZIP도 다시 생성합니다. 서버 재시작·업로드·유료 생성은 하지 않습니다. 실제 브라우저 시각 검사는 수행하지 않았습니다.

대시보드 경제 요약은 `#app`의 별도 형제가 아니라 `.wd-top > .wd-economy` 내부 전체 너비 행(`grid-column:1/-1`)입니다. 프로필·목표·하단 영역의 기존 열 순서를 유지하며, 온보딩 종료/사이드바 전환 시 본문 여백이 고정 사이드바 밑에서 애니메이션되지 않도록 `body`의 여백 전환만 제거했습니다. 넓은/좁은 화면 및 사이드바 펼침/접힘 조합의 실제 번들 구조 테스트 4개를 추가했습니다. 1440×1000 요청의 서버 측 캡처·이미지 분석에서 사이드바와 경제 요약/프로필/데일리 카드의 겹침·잘림 해소를 확인했습니다. 모바일·다크 모드·드래그 등 전체 시각 검증을 의미하지는 않습니다.

테스트는 저장 CRUD/오류/격리/백업/미디어 정리/빈 상태와 데모/fixture 제외/이전 제거 항목/원본 해시/JS 구문을 확인합니다. 가상 DOM 하네스는 **실제 빌드된 두 번들**의 부팅 및 주요 화면 이동, 빈 UI에서 직접 프로필·태스크 생성 이벤트를 실행합니다. 이 하네스는 브라우저가 아니며 시각·레이아웃·실제 파일 선택 검증을 대체하지 않습니다. Playwright/Chromium 등 새 브라우저 도구는 설치하지 않았습니다.
